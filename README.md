## 專案簡介

芒果醬活動資訊站是一個**單一頁面應用（SPA）**，以原生 HTML / CSS / JavaScript 製作，不需要安裝任何框架即可直接在瀏覽器開啟。網站把散落在社群上的演出資訊、歌單紀錄整理成可查詢、可統計、可分享的介面，讓粉絲能快速回答三個問題：

- **下一場什麼時候、在哪裡？**（近期活動）
- **過去演出都唱了什麼？某首歌出現率多少？**（場次紀錄與歌單分析）
- **今天要聽哪一首？**（隨機聆聽）

網站同時提供「我去哪芒」個人足跡功能，讓粉絲用專屬 ID 記錄自己參加過哪些場次，並解鎖成就稱號。

## 目標使用者（16–38 歲台灣年輕人）

本站以 **16–38 歲的台灣年輕樂迷**為主要對象，族群特徵與對應設計如下：

| 族群特徵 | 網站對應設計 |
|---|---|
| 高中生至大學生（16–22 歲）多以手機瀏覽、通勤或課間查資訊 | 手機優先（Mobile First）、底部導覽列、單手可操作的按鈕尺寸 |
| 社會新鮮人與上班族（23–38 歲）需要快速找到演出時間與地點 | 近期活動條列＋月曆視圖、一鍵導航地圖連結 |
| 習慣「抽卡」、「收集」、「解鎖」等遊戲化體驗 | 「我去哪芒」成就稱號（初階果汁機 → 傳奇芒果教父）、稀有度 SSSR～R 標籤、「首期待相遇」未解鎖歌曲 |
| 習慣在 Spotify、KKBOX、Apple Music、YouTube 之間切換聽歌 | 單首歌曲同時提供多平台搜尋連結與 MV 嵌入播放 |
| 常以限動、Threads、IG、Discord 分享內容 | 隨機聆聽結果可一鍵分享《歌名》，並附帶可直接開啟特定歌曲的連結（`?song=`） |
| 喜歡隱藏彩蛋與社群歸屬感 | 登入會員可看到「小果子專屬彩蛋」；支援芒果色主題（🥭）、夜間主題（🌙） |
| 重視隱私，對帳號註冊敏感 | 不強制註冊，只需輸入或建立「專屬 ID」即可使用；目前僅儲存 ID 與暱稱 |

### 族群需求摘要

- **即時性**：演出資訊、歌單回報需要快速更新，因此採用「本地 JSON ＋ 雲端試算表」雙來源載入。
- **行動性**：超過多數流量來自手機，所有操作需在 360px 寬度下仍可完整使用。
- **參與感**：粉絲可以回報歌單（場次補充）、補全資料，形成社群共建。
- **輕量**：不需下載 App，開網址即可使用，適合在社群中直接分享。

## 頁面與功能說明

### 1. 首頁
- **Upcoming Events 近期活動**：預設顯示前 3 場，可展開全部；切換「📋 條列 / 📅 月曆」。
- **月曆**：週一為第一天；有演出的日期顯示城市縮寫（超過一場會以 `*數量` 標示）。
- **歡迎區**：快速入口（隨機聽一首、查看歌單分析、瀏覽詳細場次）。

### 2. 詳細場次
- 年度列（🌟 當年度 ／ ⏪ 往年回顧 ／ 🏆 歷年總計）。
- 足跡月曆：點選日期可在右側（桌機）或下方（手機）看到當日場次，並可直接勾選。
- 場次卡片：點擊展開歌單；勾選「我去芒過」後按「儲存場次紀錄」。
- 未登入時，點擊儲存會引導前往「我去哪芒」。

### 3. 歌單分析
- 「歌曲機率即時檢索」：輸入歌名即可看到總場次、最近 4／8／12 場的出現率。
- 「最近 N 場機率排行」與「總場次機率排行（含名次升降 ▲▼）」並列比較。
- 狀態標籤：
  - ❄️ **冬眠中**：總榜前 15 名，但近期完全未唱。
  - 💎 **中樂透啦**：總出現率 ≤20% 的稀有曲，近期卻登場。
  - 🔥 **發燒中**：近期出現率比歷史平均高出 15% 以上。
- 稀有度：`R`（≥71%）、`SR`（41–70%）、`SSR`（11–40%）、`SSSR`（≤10%）。

### 4. 隨機聆聽
- 抽選時會快速跳動歌名，最後停在結果。
- 結果包含：稀有度、總出現率、多平台連結（Spotify／KKBOX／Apple Music／YT Music／YouTube）、歌詞。
- 若該歌曲有 YouTube MV 連結，會直接嵌入播放；若受官方限制無法內嵌，會顯示前往連結提示。
- **連續隨機**：播完自動抽下一首（使用洗牌袋，不會連續重複）。
- **分享**：分享頁面 `?tab=random`，或分享特定歌曲 `?tab=random&song=歌名`。

### 5. 我去哪芒（個人足跡）
- 登入：輸入專屬 ID（格式例：`MG-A1B2`）；或「建立新的專屬 ID」。
- 成就稱號依參加場次數決定：

  | 參加場次 | 稱號 |
  |---|---|
  | 0–2 | 初階果汁機 |
  | 3–7 | 活躍小果子 |
  | 8–14 | 狂熱芒果粉 |
  | 15–24 | 頂級芒果神徒 |
  | 25+ | 傳奇芒果教父 |

- 儀表板：現場解鎖進度、參與場次、共聽過首數、總時數、待解鎖歌曲。
- 金曲收藏庫：可依「出現率」或「聽過次數」排序。
- 會員限定：近期活動中可能出現「小果子專屬彩蛋」。

### 6. 場次補充回報
- 填寫活動日期（8 位數，例：`20260816`）、活動名稱、表演時間、備註、回報者名稱。
- 搜尋歌曲加入歌單，可調整順序、標記安可、移除。
- 送出後進入「待審核場次」清單；若日期重複會標示「重複日期」。

## 技術架構

```
瀏覽器（index.html 單一檔案）
├── HTML：頁面結構（導覽列、首頁、場次、分析、隨機、我去哪芒、回報）
├── CSS：CSS 變數主題系統（light / dark / mango）＋響應式斷點
├── Vanilla JS：狀態管理、月曆、排行計算、YouTube IFrame API 控制
├── Chart.js 4.4.3（CDN）：歌曲累積出現曲線
├── YouTube IFrame API：MV 內嵌播放
├── Google Fonts：Inter
└── Google Analytics 4：流量統計（G-8RJYXX12BE）

資料來源（依序嘗試）
1. ./upcoming.json（靜態檔案，優先）
2. Google Apps Script Web App（備援：getInitialData / getSetlistData）
3. 背景載入：getEventsData（完整場次歌單）
```

### 主要技術特點
- **零建置**：不需 Node.js、Webpack 或 npm，修改後重新整理即可看到結果。
- **資料與程式分離**：歌單、場次、連結、公告都來自 JSON 或試算表，不需改程式即可更新內容。
- **統計即時計算**：所有出現率、排行、稀有度皆在前端由場次資料即時算出。
- **狀態持久化**：使用 `localStorage` 保存登入 ID 歷史與主題偏好。
- **可分享的深層連結**：透過 URL 參數 `tab`、`song` 直接開啟指定頁面或歌曲。

## 資料格式

### `upcoming.json`（靜態資料，建議放在與 `index.html` 相同目錄）

```json
{
  "announcement": {
    "enabled": true,
    "text": "下一場演出已開放回報，歡迎來補全歌單！",
    "isMarquee": false,
    "updatedAt": "20261007"
  },
  "upcoming": [
    {
      "date": "20261115",
      "name": "台北 演出名稱",
      "time": "19:30-21:00",
      "location": "場地名稱",
      "mapLink": "https://maps.google.com/?q=...",
      "note": "售票資訊：https://example.com",
      "secretNote": "（僅登入會員可見）"
    }
  ],
  "songs": ["我喜歡你", "歌名 B"],
  "songLinks": {
    "我喜歡你": {
      "spotify": "https://open.spotify.com/...",
      "kkbox": "https://www.kkbox.com/...",
      "appleMusic": "https://music.apple.com/...",
      "ytMusic": "https://music.youtube.com/...",
      "ytMv": "https://www.youtube.com/watch?v=XXXXXXXXXXX",
      "lyrics": "歌詞全文（換行以 \\n 分隔）"
    }
  }
}
```

| 欄位 | 說明 |
|---|---|
| `date` | `YYYYMMDD` 八位數字，排序與月曆依此欄位運作 |
| `note` | 支援 `標籤：網址` 格式，會自動轉為可點擊連結 |
| `songs` | 歌曲主清單，隨機聆聽與歌單分析以此為基準 |
| `songLinks` | 各平台連結與歌詞；缺少的平台會自動改用搜尋連結 |
| `announcement.updatedAt` | 公告版本；更新此值後，先前關閉的公告會重新顯示 |

### 場次資料（來自 GAS 試算表）
每場 `event` 物件包含：`id`、`date`、`name`、`timeStr`、`location`、`mapLink`、`note`、`durationMins`、`setlist[]`（每首含 `songName`、`orderStr`、`isEncore`）。

## 後端 API（Google Apps Script）

部署為 Web App 後，前端透過 `GAS_API_URL` 呼叫以下 `action`：

| action | 方法 | 用途 |
|---|---|---|
| `getInitialData` | GET | 近期活動、歌曲清單、歌曲連結、公告 |
| `getEventsData` | GET | 全部歷史場次與歌單 |
| `getSetlistData` | GET | 完整資料（備援，當 JSON 讀取失敗時使用） |
| `getUserData` | GET | 依 ID 讀取使用者參加場次與暱稱 |
| `saveUserData` | POST | 建立或更新使用者資料（`userId`、`attendedEvents`、`nickname`） |
| `submitEventReport` | POST | 送出場次補充回報 |
| `getPendingEvents` | GET | 取得待審核場次 |
| `verifyAdminId` / `verifyAdminPassword` | GET / POST | 管理者驗證（前端目前尚未開放入口） |

**請求格式**
- GET：`?action=...&參數=...`（URL encode）
- POST：`Content-Type: text/plain`，Body 為 JSON 字串（避開 CORS 預檢）。

**回應格式**：`{ "success": true, ... }` 或 `{ "success": false, "error": "..." }`。

> 若頁面以 Google Apps Script 內嵌（`google.script.run`）開啟，會自動改用 `google.script.run` 呼叫，不需經過 fetch。

## 響應式設計

本站以 **三個主要斷點**涵蓋手機、平板、摺疊機與桌面：

| 裝置類型 | 寬度範圍 | 版面特性 |
|---|---|---|
| 折疊機外螢幕／極窄手機 | `≤ 360px` | 單欄、導覽文字縮小、隱藏次要說明文字 |
| 一般手機 | `≤ 767px` | 頂部精簡列＋**底部 4 格分頁列**（首頁／場次／分析／隨機）；歡迎區按鈕垂直堆疊；彈窗改為底部抽屜 |
| 大手機橫向／摺疊機展開／平板直向 | `600px – 899px` | 場次卡片與月曆、詳情並排為雙欄；隨機聆聽三鍵排列 |
| 摺疊機雙螢幕（分割視窗） | `horizontal-viewport-segments: 2` | 場次與排行改為左右雙欄 |
| 桌面／平板橫向 | `≥ 900px` | 頂部導覽列（含編號）、場次卡片 2 欄、月曆與詳情並排、彈窗置中 |
| 寬螢幕 | `≥ 1280px` | 內容最大寬度 1200px，置中，卡片內距加大 |
| 手機橫向（高度受限） | `orientation: landscape` 且高度 `≤ 500px` | 導覽列與分頁列高度縮減，影片比例調整 |

其他細節：
- 尊重系統的「減少動態效果」設定（`prefers-reduced-motion`）。
- 支援 iPhone 安全區域（`env(safe-area-inset-*)`）。
- 觸控目標最小 44px。
- 允許使用者縮放頁面（已移除 `user-scalable=no`，提升無障礙性）。

## 本機執行與部署

### 本機預覽
1. 下載 `index.html` 與 `upcoming.json` 放在同一個資料夾。
2. 使用任一靜態伺服器開啟（直接以 `file://` 開啟時，`fetch` 可能被瀏覽器阻擋）：
   ```bash
   python3 -m http.server 8080
   ```
3. 瀏覽器前往 `http://localhost:8080`。

### 部署至 GitHub Pages
1. 建立 GitHub Repository，上傳 `index.html`、`upcoming.json`。
2. 進入 **Settings → Pages**，Source 選擇 `main` 分支根目錄。
3. 幾分鐘後即可透過 `https://<帳號>.github.io/<repo>/` 存取。

### 更新內容的流程
- **改公告或近期活動**：修改 `upcoming.json` 後 push，網站會自動讀取最新資料。
- **改歌單或場次**：透過網站「場次補充回報」提交，或直接更新 Google 試算表。
- **改版面或功能**：修改 `index.html` 後重新部署。

## 已知問題與改進建議

### 已知問題（依程式碼觀察）
1. **ID 登入非驗證機制**：目前只要知道 ID 即可讀取、修改該 ID 的資料，建議未來加入密碼或 Google 登入。
2. **GAS 網址公開於前端**：屬於公開 Web App，建議限制寫入權限並加上速率限制。
3. **`<script>`（gtag）位於 `<html>` 與 `<head>` 之間**：不符合 HTML 規範，建議移入 `<head>`。
4. **部分樣式寫在 inline style**：維護與主題切換不易，建議逐步抽成 class。
6. **`esc()` 只處理單引號**：用於 `onclick` 字串時，若歌名含特殊字元可能有風險，建議改用 `data-*` 屬性與事件委派。
7. **模糊比對場次 ID**：`isEventAttended` 以 `ev.name.includes(rest)` 比對，可能造成誤判，建議統一使用穩定 ID。
8. **使用 `alert()` 與 `prompt()`**：在行動裝置上體驗較差，建議改為 Toast 或自訂對話框。
9. **年度預設以系統年份為準**：跨年時若尚無新年度場次，會顯示「陸續解鎖中」提示。

### 功能改進建議（依 16–38 歲族群）
- **加入行事曆（.ics）匯出**：上班族與學生最常用的需求，可直接加入 Google／Apple 行事曆。
- **PWA（可安裝至主畫面）**：加入 `manifest.json` 與 Service Worker，離線也能看到最近一次的資料。
- **OG 分享卡片**：為分享連結加上 `og:image` 與 `og:title`，讓 Threads、IG、LINE 的預覽更吸睛。
- **售票提醒**：可結合 Google Calendar 或 LINE Notify 類服務提醒開賣時間。
